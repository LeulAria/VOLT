+### Running ACE without a Descriptor
+When starting up your add-on server with a descriptor, ACE is capable of automically registering/deregistering your app with your host and configuring it with routes from the descriptor. However, when migrating to Forge, you may no longer have any use for the descriptor file and therefore, may want to run ACE without it. In this case, it is important to be aware of the following changes in functionality:
+
+- ACE will no longer automatically register your add-on, re-register on changes to the descriptor, and de-register on shutdown.
+  - The `AC_OPTS` environment variables will not change this behaviour
+- ACE will no longer automatically generate routes based on the descriptor definition. For example, the `/installed` lifecycle handler or any webhook handlers defined in the descriptor will no longer be generated.
+  - If your add-on requires these, you will have to implement them manually.
+  - Any authentication middleware can be leveraged by configuring the `localBaseUrl` or `allowedBaseUrls` fields in `config.json`
+- The `createJwtPayload` method, exposed as part of the `HostClient` class, defaults to using the add-on key if an issuer is not provided as an argument.
+  - This default behavior can be maintained by configuring the `appKey` field in `config.json` or passing in the `AC_APP_KEY` environment variable.
+
+As long as your add-on continues to use any connect modules, the descriptor should not be deleted.
